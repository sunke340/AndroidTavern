## 0. 一句话方案

把「**收到文本**」与「**显示文本**」拆开：SSE 收到的全文继续写进现有 `inflight.text`（请求、流式、
ViewModel 数据路径全不动）；界面只渲染「已揭示的**前缀**」，前缀按用户选的**码点/秒**匀速推进；
气泡高度等于这段前缀**自己排版出来**的高度——打印期间**布局即真相**，不使用平滑高度追高、
不使用 `translationY` 桥接、不使用 spring/tween 追文本高度。
落库后打印可继续（游标按稳定 `uiKey` 跨 `settle` 存活）。
**程序永不自动加速、不自动切档、不设最长打印时长。**

### 1.4 代码与文档的只读核实结果

**【已验证】身份与收尾**（`ChatViewModel.kt`）

- `ChatRow` 不变量 K1–K5：`uiKey` 在行存活期内**永不改变**；命名空间 `m{dbId}`/`u{seq}`/`p{seq}`；`dbId` 不参与 key。

- 收尾是**一次 `_state.update`**（源码注释：不露出"行已加、生成中还没清"的中间帧）。
- `UiState.streamingText = inflight?.text.orEmpty()`；`stop()` → `settleClaimed(text = null)` → 取 `streamingText`（**全文**）。

**【已验证】重新生成与 swipe**

- `regenerateLast()`：要求 `last.dbId != null`；不 trim `rows`；`beginCompletion(rows, userText = null, …)`；开 `Collapse(roundId, replyUiKey)`。
- 收缩窗口内 token 只进本地 buffer、**不推** `inflight.text`。

**【已验证】串流跟随符号的真实作用范围**

| 符号 | 作用 |

| `followBridgePx()` | v180 唯一判定点：入场未完成 / 收缩窗口 / 基线未建立 → 0，否则 `自然−平滑` |

**【已验证】pitfalls**（[pitfalls.md:619-684](dev/pitfalls.md)）

- `reverseLayout` 摆放 `y_top = H + o − h`：**h 变大而 o 不变 → 内容整体上移 Δh**（"贴底时长高 = 一帧整屏瞬移一行"）。
- v112"累积补偿 + 180ms 收回"在事件频率接近动画时长时必然失稳（6190 字回复 → 抽搐）→ 改为"一条动画追高度"。
- 桥接**已知未修**：从贴底切出去那一帧 `translationY` 归零，欠账大时会往上收一下。

**【已验证】工程限制**：本机 2 核 / 1.7 GiB / 无 Android SDK → **编不了 `:app`**；无 KVM → 无模拟器；
每轮验证 = CI 出包（约 2 分钟）+ 下载 15–20 分钟 + 真机回执。

**【待核实】**：`Text` 在 `SelectionContainer` 内时普通点击是否被消费；单次 tick 的文本测量耗时。

### 1.5 因果链

到达是攒包、平均很慢（26 字/s），显示被做成"测量自然高度 + 滞后追赶"，于是每次攒包制造一次
"滞后 → 猛冲 → 停住"。本方案改为**从源头控制"字"进入布局的速度**：高度是"排出来的"，不是"追出来的"。

## 2. 目标

1. 回复**逐字匀速**出现（用户原话："让文字匀速打印"）。
2. 气泡长度增长**跟着打印走**。
3. 节奏由用户选的档位决定；**程序不偷偷加速**。
4. **不改变任何非显示行为**：请求体、提示词、落库内容、导出、`查看请求` 全是全文。

**非目标**：音效/光标装饰；不改既有历史消息；不做逐字样式动画。

## 3. 方案

### 3.1 数据流（数据路径零改动）

```
SSE delta → inflight.text（全文，现有逻辑不变）
                 ├── 揭示游标 revealed（页级状态，不进 UiState）
                 └── 渲染 shownContent.takeByCodePoints(revealed)
                          └── 气泡高度 = 该前缀的自然排版高度（布局即真相）
```

无第二套文本缓冲：`inflight.text`（生成中）/ `row.content`（收尾后）是唯一来源，游标是它的**码点下标**。

### 3.2 揭示单位：全链路统一为 **code point**

**【评审结论】唯一计数单位 = Unicode 码点。全链路禁止混用 UTF-16 code unit。**

| 出现位置 | 单位 | 规则 |
|---|---|---|
| `receivedCount` | 码点 | 不得用 `String.length`；见 3.2.1 的增量算法 |
| `revealed` | 码点 | `∈ [0, receivedCount]`，单调递增 |
| `pending` | 小数码点 | `< 1.0` |
| 截取 | 码点→索引 | `idx = text.offsetByCodePoints(0, k)`，`substring(0, idx)`；`k ≥ receivedCount` 返回整串 |
| `min / clamp` | 码点 | settle 与打断时一律按码点夹取 |
| 追上判定 | 码点 | `revealed >= receivedCount` |
| 看门狗剩余 | 码点 | `receivedCount - revealed` |
| 日志 | 码点 | 字段写明单位：`显示=842cp 收到=1200cp` |
| `String.length` | 仅允许 | 作 `codePointCount`/`offsetByCodePoints` 入参、判空。**不得**用于速率/比较/剩余/字数 |

**【已验证】API**：`String.codePointCount` / `offsetByCodePoints` 是 `java.lang.String` 方法，Android 全版本可用，**无需依赖**。

#### 3.2.1 码点计数的增量算法（本轮补充 2）

**【评审结论】** 文本追加时**只数新增后缀**，不做全文扫描：

```
onTextChanged(newText):
  if (newText === prevText) return                        // 引用未变
  if (prevText != null && newText.length > prevText.length
      && newText.startsWith(prevText)) {
      // 追加：只数后缀；若 prevText 末尾是高代理、newText 第一个新字符是低代理，
      // 该代理对已被 prevCount 计入 → 后缀计数减 1（避免重复计数）
      suffixStart = prevText.length
      var add = newText.codePointCount(suffixStart, newText.length)
      if (suffixStart > 0 && newText[suffixStart - 1].isHighSurrogate()
          && newText[suffixStart].isLowSurrogate()) add -= 1
      count = prevCount + add
  } else {
      count = newText.codePointCount(0, newText.length)     // 非追加：全文重数
  }
  prevText = newText; prevCount = count; return count
```

**全文重数只允许出现在**：① 新一轮首次取文本；② 非追加变化（swipe 换正文、重新生成收尾换正文）；
③ settle 源切换（`inflight.text` → `row.content`）；④ 防御性校验（可选，v1 不做逐次校验）。
**禁止**每个 SSE delta 无条件全文扫描。

**【风险】** 若首版为省事保留全文扫描：2000 字 × 26 delta/s ≈ 5.2 万码点/s 的重扫，属于明确性能风险，
须写进 `打印帧` 日志观测，先实测后优化（§3.11 的触发条件）。

#### 3.2.2 v1 边界规则：纯码点（方案 A）

**【评审结论】v1 = 纯码点切分，不做自研组合安全扩展。**

- **保证**：不切断 UTF-16 代理对 → **不出现半个码位/豆腐块**（唯一硬性保证）。
- **不保证（明确记录）**：以下多码点组合在中途可能以**分离形态**显示，持续 ≤ 1/速率 秒
  （70 字/s≈14ms，15 字/s≈67ms）：组合附加符（`e`+U+0301）、ZWJ 组合 emoji（👨‍👩‍👧 计 5 码点）、
  肤色修饰（👍🏽 计 2 码点）、区域指示符旗（🇨🇳 计 2 码点）、keycap（1️⃣ 计 3 码点）。
- **不实现自研"组合安全扩展"**：无法严格说明边界规则与覆盖范围，写了也只是"部分正确"。
- **升级路径**：`android.icu.text.BreakIterator.getCharacterInstance()`（ICU，API 24+，本项目 minSdk 26，
  **无新依赖**）做 UAX#29 分段；需额外维护增量边界表 + 跨 delta 未完成 cluster 的尾部保留。
  **v1 不做**，触发条件：用户反馈 emoji 被拆得难看。

### 3.3 推进器、pending 语义与 dt 规则

**【评审结论】速率 = 目标速率（有充足文本时按它推进）兼硬上限（任何情况不超过）。**

```
rawDt = now − lastTickNanos;  lastTickNanos = now
if (rawDt > PAUSE_GAP) { pending = 0; lastAdvanceNanos = now; return }   // PAUSE_GAP = 1s
dt = min(rawDt, MAX_TICK)                                               // MAX_TICK = 50ms
if (revealed >= receivedCount) return        // caught-up：不累计时间、不写状态、**保留 pending**
pending += ratePerSec * dt / 1e9
n = floor(pending)
if (n > 0) { pending -= n; revealed = min(revealed + n, receivedCount); lastAdvanceNanos = now }
```

| 问题 | 【评审结论】 |
|---|---|
| 速率是上限还是目标 | 两者都是 |
| caught-up 是否累计时间 | **否**（不攒额度 → 新 delta 到达不暴吐） |
| 无文本期间是否积累整数额度 | **否** |
| fractional pending 保留/清除 | **保留**（跨 caught-up 保留，`∈[0,1)`）；仅**暂停恢复**与**清除事件**归零 |
| 长时间等待后是否突发 | 不会：时间额度只在有欠账时累计；小数余量 <1，最多多吐 1 码点 |
| 是否因频繁清小数而系统性偏慢 | **不会**：追上时不清 pending（本方案的关键规则） |
| dt 异常 | 单调纳秒（不受系统时间调整影响）；`rawDt>1s` 视为暂停；`dt ≤ 50ms` |

**【风险】** `MAX_TICK=50ms` 下长期掉帧会使实际吐字低于设定值（"宁可慢也不暴吐"的取向），需真机确认。

#### 3.4.1 运行中切换档位（本轮补充 3）

**【评审结论】**

| 切换 | 行为 |
|---|---|
| 限速档 → 限速档（15/35/70 之间） | **立即采用新速率**；`revealed`、`pending`、`uiKey`、`roundId` **全部不变**；不重启打印、不回退已显示内容、不重置看门狗 |
| 限速档 → **不限速** | **立即补满**当前回复（`revealed = receivedCount`）并**清除游标** |
| 不限速 → 限速档 | 当前这条已全文显示，不回溯；新速率**只对之后新开始的打印生效** |
| 打印已结束 / 无游标时切换 | 仅影响之后的新打印 |

实现要点：速率**每 tick 从当前设置读取**（不是建游标时快照），因此切换天然生效；切换不得触发重建
`LaunchedEffect`（否则会重置 `lastTickNanos` 造成一帧抖动）。

### 3.5 最长打印时间上限

**【评审结论】不设任何时间上限。** 前提：逃生口可靠（3.6）。2000 字慢档 = 133 秒是"慢"的字面含义；
程序不得自动加速/切档/补满。唯一时限类是异常检测（3.9），正常使用永不触发。
嫌慢请改档位数值或加档，**不引入隐藏常数**。

### 3.6 打断与逃生口

| 事件 | 行为 |
|---|---|
| **点一下"正在打印"的那条气泡** | 立即清除游标（视觉=补满） |
| 点「停止」 | 立即清除（同一收尾落库） |
| 退出聊天页 / 切会话 | 立即清除 |
| 发下一条 / 重新生成 / 换 swipe | 上一条立即清除 |
| 删除该条 | 立即清除 |
| 系统「移除动画」 | 见 3.10 |
| 打印已结束 | 游标已清除，**点击无行为**（与今天一致） |

**与未来交互**：长按=选字、点击=补满（不同手势）；本项目**没有**链接检测与代码块交互
（`InlineMarkup` 只认 `<i>/<em>/<b>/<strong>/<br>`）；双击选词未实现。
**窄作用域**：仅该行打印中响应点击，打印结束不占用点击语义。

**【已验证】「复制」复制全文**：现有 `onCopy` 读 `row.content`，不受前缀影响，保持不变。

**【待核实】** `SelectionContainer` 内普通点击可达性；不可达则备用"点动作行区域"（不提前实现）。

### 3.7 Printing 生命周期

**旧规则（已废弃）**：`revealed == receivedLen → 清除`。**错在**把"暂时没欠账"当成"生成结束"，
会让慢档在新 delta 到达时整段冒出。

**【评审结论】四态区分**：

| 概念 | 定义 | Printing |
|---|---|---|
| caught-up | `revealed >= receivedCount` 且生成未结束 | **存活**、空闲等待、不累计时间、不写状态 |
| generation finished | `inflight` 变 null（或换轮） | `generationDone = true`；`receivedCount` 改由该 `uiKey` 的 `row.content` 计算 |
| finished + 有欠账 | `generationDone && revealed < receivedCount` | **继续按档位打印**（慢档的本意） |
| finished + 无欠账 | `generationDone && revealed >= receivedCount` | **此时才清除** |

#### 3.7.1 收尾一致性判定（本轮补充 1）

**【评审结论】判定不依赖任何"缓存的最后一次 inflight 文本"，只用最新状态快照里的事实。**

判定依据（全部来自收尾那一次 `_state.update` 落地后的快照，该方法本身是原子的）：

1. 该 `uiKey` **是否在 `rows` 里**（不在 → `RowAction.None`/追加失败：无行可打 → **立即清除**）。
2. 该行的 `content` 是否**仍等于本轮开始时的基线正文**（`baselineContent`，开轮那一刻从快照里取的
   该行内容；新消息没有行 → 基线为 null）。相等 → 正文没被写过 → **立即清除**。
3. 否则 → 本轮正文已提交 → `generationDone = true`；`receivedCount = codePoints(row.content)`；
   `revealed = min(revealed, receivedCount)`；若已无欠账则清除。

**为什么这样更稳**：`lastInflightText` 是**观测缓存**，可能滞后于触发收尾的那次状态发射（重组时机、
裁剪、异常路径都可能让它晚一拍）。而"行在不在"、"正文与开轮基线比是否变过"是快照事实，
不依赖缓存新旧。基线正文在整轮内不会变，是可靠锚点。

**保守取向**：任何判定失败/模糊的情况**不要清**（宁可多打一会儿），因为"误清"会让用户看到
"慢档突然补满"；而"多打"最多是慢一点。

```mermaid
flowchart TD
  A[收尾观测：inflight 变 null] --> B{该 uiKey 在 rows 里?}
  B -- 否 --> CLEAR[清除游标]
  B -- 是 --> C{row.content == baselineContent?}
  C -- 是 --> CLEAR
  C -- 否 --> D[generationDone=true<br/>receivedCount=cp(row.content)<br/>revealed=min]
  D --> E{revealed >= receivedCount?}
  E -- 是 --> CLEAR
  E -- 否 --> KEEP[继续打印]
```

**状态模型（最小实现，无第二套缓冲）**

```
Printing(uiKey, roundId, revealed, pending, generationDone, lastAdvanceNanos)
页级锚点：baselineContent（开轮时该行正文，新消息为 null）、receivedCount（码点，按 3.2.1 维护）
```

**状态转换表**（明确，不写"注意竞态"）：

| 时机 | 判定 | 动作 |
|---|---|---|
| 开轮（`inflight.uiKey` 变化） | — | 清除旧游标 → 记 `baselineContent` → 新建 `Printing(key, roundId, 0, 0f, false)` |
| 流式收字 | `revealed < receivedCount` | 按 3.3 推进 |
| 追上当前全文 | 生成未结束 | caught-up：存活、空闲等待 |
| 收尾 | 见 3.7.1 三分支 | 清除 / `generationDone` 续打 |
| 收尾后仍有欠账 | — | 继续推进 |
| 删除该行 / swipe / 换轮 / 退页 / 切会话 / 点气泡 / 停止 / 减动效 / 切到不限速 | — | 立即清除 |

**【已验证】完整性的依据**：`RowAction.Append` 与 `Rewrite` 都复用 `replyUiKey`，收尾是单次 update，
所以"同一 key 从流式走到落库"是确定事实，**不需要 `rows.lastOrNull()` 推断**。

**【待核实】** `WritePlan.*.content` 是否与 `inflight.text` 逐字符相同（trim/规整）。若不同，
3.7.1 会走"正文变过"分支继续打印——因为判定基于"是否变过"而非"是否相等"，这个设计对规整也安全。

### 3.8 重新生成与版本切换

1. **开始重新生成**：上一条游标立即清除（=补满）。
2. **开收缩窗口前**：必须已清除（否则收缩起点 `lastBubbleHeight` 取到"半打印高度"）。
3. **收缩窗口期间**：禁止推进（此期 `inflight.text` 为空，token 只进本地 buffer）。
4. **窗口关闭 + 首个 delta 到达**：为 `(uiKey, roundId)` 新建游标，`revealed = 0`。
5. **新旧版本不串用**：游标带 `roundId`，仅当 `roundId == inflight.roundId` 时推进；swipe 换正文直接清除。
6. **衔接**：窗口关闭那一帧不推进，因此不会出现"占位气泡里凭空有字"。

### 3.9 停滞看门狗

**【评审结论】语义 = 异常检测，不是节奏控制。**

- **计时条件**（同时）：`Printing != null` 且 `revealed < receivedCount`（有账）+ `rawDt ≤ 1s`（帧在来）
  + 非「移除动画」+ 非收缩窗口。
- **重置**：任何一次 `revealed` 前进；任何 `rawDt > 1s` 的暂停恢复（重置计时、丢弃 pending，不触发）。
- **触发**：`revealed = receivedCount` → 清除 → `chat 打印停滞，补齐 uiKey=p12 roundId=3 剩余=214cp 已等=5.0s`。
- **明确排除**：等模型下一批（无账）、页面进后台（无帧）、减动效（无游标）。
- **性质**：异常降级；验收单列"未出现"，出现即说明有 bug。

### 3.10 系统「移除动画」/ Reduce Motion

**【评审结论】系统可访问性优先。** 开启时：不启用游标、直接全文、不启动推进循环、忽略用户速率
（设置项仍展示），运行中切换立即生效（清除游标），记 `ui 减动效：打印直接全文`。

### 3.11 性能与观测

**【评审结论】v1 最简实现，先测量后优化；不引入设备分档、自动变速、批量吐字。**

**避免整页重组的硬约束**：

1. 游标状态**不进 `UiState`**（每 tick 写它 = 整页重组）；
2. 游标只在**打印中那一项的 item 内容 lambda**里读取（LazyColumn item 是子组合）；
3. LazyColumn 的 DSL 作用域**不得读游标**；
4. 无欠账时不写状态（3.3）→ 静止期零重组。

**成本**：item 重组 1 次/tick（仅打印行）；`takeByCodePoints` O(n) 复制；显示正则 + `InlineMarkup` O(n)
（现有逻辑本来每次重组都跑）；文本测量 O(n)、常数未知（最大不确定项）。

**日志口径（修正）**：

```
scroll 打印帧 tick=58/s 目标速率=70cp/s 实际=69.2cp/s 显示=842cp 收到=1200cp 欠账=358cp 供给足=是
```

- `tick` = 2 秒内 `withFrameNanos` **回调次数/2**，叫 **tick rate / 帧回调率**；
- **明确**：`tick` **不等于**显示帧率，**不能单独证明 UI 流畅**；v1 不采集长帧，UI 流畅度以**真机主观 + 滚动无卡顿**验收；
- `实际` = 2 秒推进码点数/2（推进器吞吐，不是渲染帧率）；
- `供给足` = 该窗口内 `欠账 > 0` 的 tick 占比 ≥ 80%；
- **优化触发（排除供给不足）**：连续 3 个「供给足」窗口 `实际 < 目标×0.8` → 实施"每 tick 吐 2–3 码点"
  或"仅可见行变化时重排"。**不得**用 `tick` 单独触发。

### 3.12 与现有串流机制的交接

| 现有机制 | 本方案下 |
|---|---|
| `translationY` 贴底分支（`followBridgePx`） | **打印期间恒 0** |
| `translationY` 读气泡分支（`streamHeight − anchoredHeight`） | **保留**（滚动补偿的一帧桥接，非高度追赶） |
| `smoothHeight` / `streamHeight` | 不参与跟随；`streamHeight` 仍用于场景 C 与诊断，`smoothHeight` 仅留给收缩窗口 |
| 入场动画 `revealFromBottom` | 保留。**【待核实】** 槽位高 `e×自然高` 与游标增长叠加观感 |
| `chromeHeight` 预留 | 保留（收尾帧高度不跳） |
| 占位气泡 | 判据仍为"还没收到第一个字"；`showCursor` 改为 `revealed > 0` |
| `collapse` 窗口 | 期间禁止推进 |

### 3.13 配置与持久化

**【评审结论】** 只做**全局一层**（设置 → 外观），不进会话/卡级（观感非内容参数）；只需
`SettingLinkRow` + 二级页一行，**不动 `ConfigKind` 三级链路**；默认「中（35 码点/s）」；存**名字/枚举**，不存序号。
运行中切换规则见 3.4.1。

## 4. 被否掉的选项

| 选项 | 否掉的理由 |
|---|---|
| 追平时间 T（弹簧/低通） | 实测即"走走停停 + 最新 7 行藏 150–600ms"；滞后与平滑不可兼得 |
| 高度匀速 px/s（夹报给布局的高度） | 需夹高+手裁；px 随密度变；把"字"的节奏让给"高度" |
| 不跟（浏览器式） | 攒包一次整块上跳 4–7 行（实测），2026-11-24 已否 |
| 自动换档 | 速度中途变化是新的观感问题，且悄悄改掉用户选择 |
| 最长打印时间上限（曾提 60s） | 魔法常数、替用户改节奏 |
| 独立缓冲队列 | 与"游标=下标"等价，多一份状态、多一处漏水点 |
| `rows.lastOrNull()` 推断收尾行 | 身份推断风险；`uiKey` 本就稳定 |
| 追上即清游标 | 混淆 caught-up 与生成结束，慢档会在新 delta 到达时整段冒出 |
| 码点 + 自研组合安全扩展 | 无法严格说明边界与覆盖，属"部分正确" |
| v1 直接上 UAX#29 grapheme | 平台 API 可用且无依赖，但需增量边界表 + 跨 delta 未完成 cluster；风险大于收益，列为升级路径 |
| 用 `String.length` 参与速率/比较 | UTF-16 ≠ 码点，全链路单位不一致 |
| 以缓存文本作为收尾判定依据 | 可能滞后 → 误判提前补满；改用快照事实（行在不在 + 正文是否变过） |
| 每次 delta 全文重数码点 | 2000 字 × 26 delta/s 的无谓扫描；改为增量后缀计数 |

## 5. 风险与未验证点

1. **【风险】** 每 tick 文本排版开销（2000 字 + 70/s）；有观测与触发条件（3.11）。
2. **【风险】** 收尾那一帧渲染源切换（`inflight.text` → `row.content`）：同 key、按码点夹取，需真机确认无闪。
3. **【待核实】** `WritePlan.*.content` 是否与 `inflight.text` 逐字符相同（判定按"是否变过"设计，对规整安全）。
4. **【待核实】** 入场动画 × 游标叠加是否有—帧错位。
5. **【待核实】** `SelectionContainer` 内普通点击可达性。
6. **【风险】** 重新生成衔接：窗口关闭后要等首个 delta 才推进，占位停留可能略长。
7. **【风险】** 慢档 + 2000 字 = 133 秒，可能被误认为"卡住"；逃生口是点气泡。
8. **【风险】** 多码点 emoji 在 v1 会出现短暂分离形态（≤1/速率 秒），已知并接受。
9. **【风险】** `Printing` 跨收尾存活：极端路径（切会话、取消）若漏清会挂在不存在的行；转换表已覆盖，实施时逐路径核对。
10. **【风险】** 增量码点计数在"代理对被 delta 切开"时需要减 1 修正（3.2.1）；若 SSE 真的切开代理对，`takeByCodePoints` 取到半个对会渲染成替换符——**这一假面由 3.2.2 的"不切代理对"保证**（切分永远落在完整码点边界），但**接收侧**若切开了代理对，UI 拿到的文本本身就已损坏，属输入问题，非本方案引入。
11. **【已验证的工程约束】** 本机编不了 `:app`、无模拟器；预计 1–2 轮真机验证。

## B. 实施最小改动清单（不写代码）

**新增状态（均不进 `UiState`）**

- `Printing(uiKey, roundId, revealed, pending, generationDone, lastAdvanceNanos)`：页级 `mutableStateOf`；
- 页级锚点：`baselineContent`（开轮时该行正文，新消息 null）、`receivedCount`（码点，按 3.2.1 增量维护）；
- 全局设置项 `revealCharsPerSec`（枚举 15/35/70/0，存名字）；
- 复用 `rememberReduceMotion()`。

**渲染（`ChatScreen`）**

- 打印行的 `shownContent` 外包 `takeByCodePoints(revealed)`（新增私有工具：`codePointCount` / `offsetByCodePoints` 换算）；
- `showCursor` 判据改为 `revealed > 0`；占位判据不变；
- `translationY` 贴底分支：打印期恒 0（在 `followBridgePx()` 加"正在打印 → 0"）；
- 点气泡：仅 `row.uiKey == printing.uiKey` 时清除；
- 「复制」保持读 `row.content`。

**事件（`ChatScreen` 侧，不改 ViewModel）**

- 开轮（`inflight.uiKey` 变化）：清除旧游标 → 记 `baselineContent` → 新建；
- 收尾：按 3.7.1 三分支；
- 停止 / 退页 / 切会话 / 发下一条 / 重新生成 / 切 swipe / 删该行 / 减动效 / 切到不限速：清除游标；
- 档位切换：不重建 `LaunchedEffect`，每 tick 读当前设置。

**推进循环**

- 一个 `LaunchedEffect` + `withFrameNanos`：`rawDt>1s` 视为暂停；`dt≤50ms`；caught-up 不累计不写状态；含 5 秒停滞看门狗。

## D. 最终评审结论

产品原则（用户选速度、程序不偷偷加速、不设时间上限、落库后继续打印）与技术机制（游标 + 布局即真相、
零桥接、零追高）已收敛；三轮评审指出的问题（生命周期、计数单位、边界规则、收尾一致性、计数性能、
运行中换档）均已给出确定解，无"视情况而定"的中间态。
剩余不确定性全部是实施中可验证的局部问题，且都带安全兜底（正文变过则续打、点击不可达则换位置、
吞吐不足则按阈值优化）。**建议通过后进入实施**，1–2 轮真机覆盖 §6 的 19 条验收项，
其中 #3（停顿后继续逐字）、#8（落库后继续打印）、#12/#13（运行中换档）、#17（emoji 不断码位）为本轮必验。

## F. 真机 v181 回执后的三条修正（2026-11-27 上午，`apk-m221`）

第一批真机回执（装 `apk-m220`，日志 `tavern-log-20261127-084559`）报了三件事，两件落在揭示节奏上。

### F.1 「新会话第一条回复仍是旧动画 + 抽动」的根因：看门狗把"等首字"算成了停滞

日志证据（同一轮，`p2` / roundId=1）：

| 时刻 | 日志 | 说明 |
|---|---|---|
| 08:39:13.416 | `打印开始 uiKey=p2 roundId=1 速率=15cp/s` | 游标建在**占位气泡**上，此时正文为空 |
| 08:39:15.464 / 17.484 | `打印帧 … 显示=0cp 收到=0cp 供给足=否` | 模型还没吐第一个 token |
| 08:39:19.091 | `打印停滞，补齐 uiKey=p2 剩余=1cp 已等=5.613755278s` | 首字刚到，看门狗立刻判超时 → 清游标 |
| 之后 | `串流帧 … 桥=70/210/475…` | 游标已清，整轮退回 v180 的桥接老路径（用户看到的"老版动画 + 抽动"） |

**根因**：`RevealPacer.stalledFor()` 记的是"距上次真正前进"的时间，而"追平态"（`revealed >= received`，
没有账可还）**不会**刷新它。于是模型思考的那 5 秒被记成停滞；首字一到，`revealShown(0) < received(1)`
成立，看门狗立刻触发补齐 —— 整轮作废。

**修法**：`step()` 的追平分支里把计时器洗到此刻（`lastAdvanceNanos = nowNanos`）。
语义变成"**有账可还却没前进**才算停滞"，这才是异常检测该有的口径。
单测：`RevealPacerTest.等首个 token 的几秒不算停滞`（先红后绿验证过：去掉这行就 FAILED）。

**为什么不是改阈值**：把 5 秒调大只是把"首字慢"的运气变好一点；换台机器、换个模型、思考 20 秒又会复发，
而且会同时钝化真正的异常检测。口径错就改口径。

### F.2 「重新生成时，字还没打完，右下角 ●/● 切换按钮就冒出来」

`showSwipeBar = !state.isStreaming && …` 判的是**生成**状态，而揭示节奏把"生成结束"与"打完"
拆开了 —— 落库那一刻 `isStreaming` 就 false，可屏幕上还剩几百个码点没打。

**修法**：打印期的"动作行 + 版本条"**只占位、不显示**（`chromeDeferred`）。

- 高度用 `settledChrome`（= 打完那一刻真身的高度）预留，所以打完不会跳（这正是本方案验收项 8
  "动作行/版本条不跳"的要求）；
- 顺带把动作行也一起延后：字还在一个个出来时，"复制"能点、点下去却是全文，比看不见更让人困惑；
  想立刻拿回按钮，点一下气泡补满即可（§3.6 的逃生口）。

### F.3 「聊天页右上角 ⋮ 点不动」（同批真机回执第 1 条，不是揭示节奏的锅）

日志里没有"弹了但看不见"，而是直接：

```
11-27 08:40:32.639  W  ui  胶囊菜单请求没有宿主
```

`GlassDetailScaffold` 里喂给页头 `actions` 的那个 `CompositionLocalProvider` 只提供了
`LocalSheetController` / `LocalConfirmController`，**漏了 `LocalCapsuleMenu`**。
页面在 actions 里读 `.current`，拿到的是"没有宿主"的默认实例：`show()` 只留一行日志，屏幕上什么都不弹。

**修法**：补上这一行；并新增结构守卫 **INV-11b**（骨架里紧跟 `DetailHeader(` 的那个 provider
必须提供 `LocalCapsuleMenu`，按括号配平取实参，自测删掉该行会红）。

> 教训：这类"静默失败"必须在骨架层由结构守卫兜住 —— 真机上没有任何视觉反馈，只能靠日志反推，
> 而用户根本不会去看日志。
