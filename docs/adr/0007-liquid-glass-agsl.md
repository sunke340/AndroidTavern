# ADR 0007 · 液态玻璃走 AGSL，玻璃档门槛提到 API 33

- 状态：已采纳（2026-11-23）
- 影响面：`app/LiquidGlass.kt`（新增）、`app/Glass.kt` 的 `liquid` 分支、`VisualEffects.effective()`、
  设置 →「外观」的视觉效果行；发送钮的首个使用者
- **不改**：ADR 0005/0006 的"内容录图层 + 在节点上挂 blur"这套（底栏/页头/输入框继续用它）

## 背景

发送钮的高光前后改了五版：主色调白 72% → 92% → 纯白 → 加 `clip` → 内缩半个线宽 → 单圈细线。
每一版都能在截图上量出问题，但用户始终觉得"不对"，最后一句很准：**"这个设计还是有问题"**。

根因不是参数，是模型：我们一直在做"半透底 + 描边 + 高光"，也就是玻璃的**表皮**。
真正的 Liquid Glass（WWDC25）是三件套：

1. **透镜折射** —— 边缘把背后的内容弯折进来；
2. **镜面高光** —— 边缘朝光一侧的反射；
3. **自适应色调** —— 按背后内容调整明暗，保证可读。

没有第 1 条，任何"高光"都只能是一条线；而在浅色面上一条线的亮度天花板就是背景色本身，
所以怎么调都"看不出来"或"太假"。

## 决策

1. **用 `RuntimeShader`（AGSL）做真折射**，只作用于**发送钮**（第一个试点）。
   实现是 SDF 位移场：`sdRoundRect` 出"离边界多远 + 法线"，只在边缘 `edgeDp` 带内把采样点
   沿法线往外推，再对 R/B 通道用略微不同的偏移做出很淡的色散；边缘按法线点乘光方向出高光，
   底部压一道内阴影定厚度。数学照 [shuding/liquid-glass](https://github.com/shuding/liquid-glass)
   的位移场，参数照 [skydoves/Cloudy](https://github.com/skydoves/Cloudy) 的命名（后者要
   AGP 9.2 / Kotlin 2.4 / Compose 1.11，**不能直接引依赖**，跟 Haze 2.0 同一个坑）。
2. **底片复用已有链路**：糊涂层 `frost`（内容层 1/8 降采样）就是着色器的 `uContent`，
   模糊挂内层节点、着色器挂外层节点（同一节点只能有一个 `renderEffect`）。
   不需要额外截图、不需要第二套录制。
3. **玻璃档门槛从 API 31 提到 33**（`glassSupported`）。低于 33 没有 AGSL，
   **不退回那套彩色玻璃**，直接降成轻量：`VisualEffects.effective()` 是唯一入口，
   所有渲染点都必须用它，设置页在低版本连"玻璃"选项都不显示。
4. 着色器编译失败要**兜住**：`runCatching` + `AppLog.e("glass", …)` + 退回描边样式，
   绝不让一颗按钮把 App 崩掉。

## 后果

- 发送钮在"有内容经过它背后"时（消息滚到输入区后面）才能看出折射 —— 底片是纯色时
  物理上就该是平的，这不是 bug。
- AGSL 每帧离屏渲染一次，一颗 44dp 的钮可忽略；**推广到底栏/页头前要先量帧率**。
- 将来推广时，`LiquidGlassSpec` 是唯一的参数面（`edgeDp` / `refraction` / `dispersion` /
  `specular` / 光源方向），不要再散落常量。
