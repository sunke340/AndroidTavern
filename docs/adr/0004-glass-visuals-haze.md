# ADR 0004 · 玻璃视觉用 Haze（1.5.x），并且只做"轻玻璃"

- 状态：已采纳（2026-11-22）
- 影响面：`app` 模块的依赖与视觉层；`data` 新增一个偏好字段（`visual_effects`）
- 关联：[app/AGENTS.md](../../app/AGENTS.md) 的"界面上不写解释性文案"、`docs/dev/status.md`

## 背景

`C · Dense Ink` 方向（细线分隔、1px 描边、无阴影）在真机上被判定"简陋、太多直线、没有圆角"，
用户要求往 **液态玻璃（iOS 26 Liquid Glass）** 靠。

iOS 那套的要素里，**背景虚化**和**边缘折射**是系统级能力；Android 没有对应公开 API：

- `Modifier.blur` 只模糊**自己**的内容，糊不到背后的东西；
- `RenderNode.setBackdropRenderEffect` 是 Android 17 QPR2（SDK 37.2）才有的，不能依赖；
- 自己实现的路子是"把背景内容录进 `GraphicsLayer` → 裁到面板 → 加 `RenderEffect` 模糊"，
  约 200 行，且模糊要求 API 31+、折射（AGSL）要求 33+。

## 决策

1. **引第三方库 `dev.chrisbanes.haze:haze`**，破例理由见下。
2. 版本**锁 1.5.4**：它是最后一个依赖 `Compose 1.7.3 / Kotlin 2.1.0` 的版本，正好对齐我们的
   `compose-bom 2024.12.01`（Compose 1.7.6）与 Kotlin 2.1.20。
   证据（Maven Central 的 POM）：`1.5.4 → compose 1.7.3 / kotlin 2.1.0`、
   `1.6.0 → compose 1.8.0`、`2.0.0 → kotlin 2.4.20`。**升 2.x 要先升整条工具链，另开 ADR。**
3. **只做"轻玻璃"**（路线 B）：悬浮胶囊底栏 + 背景模糊 + 半透明 + 1px 描边 + 投影 + 圆角体系。
   **不做**边缘折射/色散（那要 AGSL 且只在新系统生效，收益不抵成本）。
4. 低版本降级由 haze 负责（API < 31 无模糊）；我们额外提供**用户可见开关**：
   设置 → 外观 → 视觉效果 = `玻璃` / `轻量`（`blurEnabled = false` 时不模糊，只留半透明底）。

## 为什么破"不引第三方 UI 库"这条

那条规矩的本意是**省依赖、省编译时间、减少 CI 失败面**（本机编不了 Android 模块）。
模糊这件事的坑在于：录制层级、裁剪、脏区重绘、不同 API 的降级——自己写 200 行要反复上真机调，
而 CI 一轮 4 分钟。Haze 是这块事实上的标准实现，且**不引入 Compose 之外的东西**（无 OkHttp/Room 类负担），
体积几十 KB。权衡下来引库更划算。**除它之外仍然不引别的 UI 库**（navigation-compose、Coil、
material-icons-extended 依旧不引）。

## 后果

- 好：底栏/弹层可以做成"内容从底下透出来"的真玻璃；后续页头、卡片、聊天气泡可直接复用同一套效果。
- 坏：多一个依赖，且**被钉在 1.5.4**——想升级必须同时升 Compose/Kotlin，属于一次独立迁移。
- 性能：模糊是每帧一次离屏绘制。**拿真机先看滚动**；掉帧就让用户切「轻量」，或把默认值改成轻量。
- 回退：视觉效果关掉即等价于"无模糊"；再不行整个依赖与底栏改动可以退回 tag `apk-m27`。

## 未做

- 折射/色散（AGSL，API 33+）
- 页头、卡片、聊天气泡的玻璃化（本轮只动底栏，先验证库在真机上真的工作）
