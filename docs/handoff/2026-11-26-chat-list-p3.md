## 一、P3 干了什么（已通过，M26）

| 事 | 一句话 | 细节 |
|---|---|---|
| **就地改写** | 重新生成不再"撤下旧行 + 收尾追加新行"，而是**同一行改写**：`inflight.uiKey` 直接用那条消息原来的 `m{dbId}`，收尾按原行号 `replaceMessage` | 删掉四个 P0/P1 适配器：`ReplaceTarget` / `GenerationRound.removedContent`（+`RowAction.RestoreRemoved`）/ `Inflight.removed` / `UiState.streamingRegenerate` |
| **开场平滑收缩** | 旧正文被高度裁掉、宽高一起收、正文渐隐；收完换成 `重新生成中`（渐显）；首字再长出来 | 高度**显式驱动**（`Modifier.height` 的等价物 `clampReportedSize` + `Animatable`），不是 `animateContentSize` |
| **收尾涨回** | 0 字停止 / 失败时旧正文从占位高度**长回**原高度；窗口是收尾时**补开**的 | `UiState.collapse = Collapse(roundId, uiKey, growBack)` |
| **入场动画** | 新行**槽位高度从 0 长到自然高**（气泡从输入框后面升起来）+ 淡入；按"出厂序号"认新行 | `revealFromBottom(progress)`；判据 `bornSeq(uiKey) > bornFloor` |
| **发送错峰** | 用户气泡先升上来，停约 100ms，占位气泡再升上来 | 两行**同帧进列表**，占位行只延后入场动画（`PendingAppearDelayMs = 480`） |

**P3 的四个"看起来对但真机不对"的坑**（每一条都花了一轮，细节在 [pitfalls](../dev/pitfalls.md)）：

1. `animateContentSize` 只动画"报给父级的尺寸"，**子内容仍按自然尺寸画** → 气泡看着不会变小。
2. 收缩窗口按"开场 380ms"关 → 模型慢的时候（TTFT 2–13s 很常见）用户点停止时早就出窗口了，
   涨回瞬跳。**判据应该是"界面上现在显示的是不是占位"，不是"这一轮开始了多久"。**
3. 预占（动作行 34dp + 版本条 40dp）**不能一上来按满额占** —— 只有一个版本时那一行本来没有
   版本条，凭空多 40dp 就是"点下去整列抬一行字"。预占量也要跟收缩进度一起走。
4. 尺寸探针**必须放在夹尺寸的外侧**（量"屏幕上真实多高"）。放内侧会一直报自然高度，
   窗口关掉那一帧桥接以为气泡矮了 1330px，整列被拉上去再弹回 —— 就是"列表又滚一次"。

**实施时被源码纠正的一处方案**：r2 原文写 `animateContentSize(clip = true, …)`，
1.7.6 **没有 `clip` 参数**（裁剪写死在 `clipToBounds()` 里）。r2 §13.1 已按实测改写。

  `bash tools/check-core-purity.sh`、`check-kotlin-comments.sh`、`check-kotlin-imports.sh`、
  `check-ui-map.sh`、`check-ui-invariants.sh`、`bash tools/test-core.sh`（十个 core 模块 129 条）。
- **解析级语法自查**（能抓错位括号 / `@Composable` 位置 / when 少分支，抓不到类型错误）：

  [老卡](2026-11-26-chat-list-refactor.md)。判据是**和基线比**：`grep -cE 'not enough information|None of the following'`
  的数不该比 HEAD 多（2026-11-26 的基线是 8–10 条，全是缺依赖造成的噪声）。
- **出包循环**：`git commit`（消息含引号/反引号就写文件 + `-F`）→ `git push` → `bash tools/poll-ci.sh <sha>`
  （约 1–3 分钟出 APK）→ 下载 `releases/download/apk-latest/app-debug.apk?cb=<时间戳>`
  （**很慢，10–20 分钟，必须放后台 job**）→ 验 `classes17.dex` 里的 40-hex `BUILD_ID`（唯一判据）

  → `cp` 成 `artifacts/app-vNNN-<sha7>.apk` → `git tag apk-mNNN <sha>` → `git push origin apk-mNNN`。
- ⚠️ 文档提交也会触发 CI 并覆盖 `apk-latest` —— 交付以 `artifacts/` + tag 为准。

## 七、坑（一句话一条，细节在 pitfalls.md）

1. **`cancel()` 只能在拿到提交权之后**（P0 修的：否则回复在库里、界面没有）。
2. **纯 JVM 新模块要在三处登记**：`settings.gradle.kts` + `tools/test-core.sh` + **`app/build.gradle.kts`**。
3. **`WindowInsets.ime` 是 `@Composable` 属性**，不能在 `LaunchedEffect` 里读。
4. **插入本身会把 `atBottom` 翻成 false**（稳定 key 锚住旧条目）→ 回底判据用"第一可见项 ≤ 2 且 `offset == 0`"。
5. **测量状态要按轮分开**（`remember(roundId)`）。
6. **`animateContentSize` 不能用来做"气泡变小"**（见上一节坑 1）；要自己做高度 + 自己裁绘制
   （`Text` 被高度约束后**绘制不裁**），而且**别用 `clipToBounds()`**（graphicsLayer，19k px 的开销，INV-02）。
7. **重新生成别再"撤行 + 追加行"**：那是"删条目 + 建条目"，开场闪的根。行留在 `rows` 里、复用 `m{dbId}`。
8. **入场动画要动槽位高度**，只动绘制等于没动布局（列表会瞬移）。
9. **"两拍"别用"晚一点再插行"实现**：插入会让稳定 key 重锚、整列跳一下。两行同帧进列表，只延后动画。
10. **占位气泡的颜色是写死的**（`onSurfaceVariant`），不走 `LocalContentColor` —— 淡入淡出要单独传 alpha。
11. **`Modifier.animateItem` + 抑制开关会让老行重播淡入** —— P3 已改成"按出厂序号认新行"，别再装回去。
12. **提交消息里有引号/反引号就写文件 + `git commit -F`**；本机编不了 → 缺 import 只能 CI 抓。
