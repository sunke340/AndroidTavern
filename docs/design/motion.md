# 动效规矩（2026-11-23 起）

**这份文档解决一个问题**：动效好不好，靠"感觉"判断太慢、也太容易互相说服。
所以把它变成三张可以照着查的表：**该不该动**、**用什么曲线与时长**、**哪些做法直接毙掉**。

## 来源与适用范围

- 表格取自 [emilkowalski/skills](https://github.com/emilkowalski/skills)（作者 Emil Kowalski，
  Sonner / Vaul / cmdk 作者，README 自述在 **Vercel、Linear** 工作过 —— **不是苹果工程师**）。
  其中 `apple-design` 那个 skill 是把 WWDC《Designing Fluid Interfaces》等公开演讲整理成 Web 语言，
  "苹果的动效原则"这个名声主要来自它。
- 那套 skill 的主体是 **Web/React 专属**（viewport、`hover: hover`、`touch-action`、Motion/Framer 参数、
  `@starting-style`、Vaul），**照抄进 Compose 只会变成噪音**。这里只留三块跨平台成立的东西：
  决策闸门、曲线/时长、手势物理。
- 我们的取值落在 `app/src/main/kotlin/app/tavern/Motion.kt`；**动效常量不要写进页面**。

## 一、该不该动（先过这道闸）

| 出现频率 | 结论 |
|---|---|
| 100 次/天以上（键盘快捷键、命令面板开合） | **不要动效**，到此为止 |
| 几十次/天（列表跳转、悬停类） | 只做"几乎察觉不到"的：要么极短极轻，要么不做 |
| 偶尔（弹层、抽屉、页面切换） | 标准动效 |
| 罕见/首次（引导、成功、庆祝） | 才允许"为好看而动" |

过了频率闸，再问一句**目的是哪个词**：反馈 / 空间连续 / 状态指示 / 避免突兀 / 解释 / 取悦（仅限罕见档）。
**说不出目的就别做。**

## 二、曲线与时长

**缓动**（决策顺序）：

| 场景 | 曲线 |
|---|---|
| 进入 / 退出（新内容出现、页面切换） | **ease-out**（强版） |
| 屏幕上移动 / 形变 | ease-in-out |
| 颜色、悬停类 | ease |
| 匀速（进度、跑马灯） | linear |
| 拿不准 | ease-out |

**Compose 里的对应值**（`Motion.kt`）：

```kotlin
Motion.Decelerate = CubicBezierEasing(0.25f, 0.46f, 0.45f, 0.94f)  // ease-out-quad，进/淡入
Motion.Standard   = CubicBezierEasing(0.2f, 0f, 0f, 1f)            // 退场位移（M3 emphasized）
```

- **禁止 `ease-in`**：它起步慢，正好把用户盯着看的那一刻拖住。同样 200ms，ease-out 感觉更快。
- **进入曲线怎么选，别看"是不是 ease-out"，看它把位移摊在哪里**。240ms 的翻页实测
  （数字 = 该时刻已走完全程的百分比）：

  | 曲线 | 10% 时间 | 25% | 50% | 视觉上走完 |
  |---|---|---|---|---|
  | `(0,0,0,1)` | — | — | — | 起步斜率无穷大，读成"弹射" |
  | `(0.23,1,0.32,1)` 强 ease-out | 40% | 78% | 97% | ~75ms（240ms 只用掉 1/3） |
  | `(0.25,0.46,0.45,0.94)` **现在** | 19% | 45% | 77% | ~155ms |

  强曲线在数学上更"利落"，但用户的实际反馈是"翻页有点太快"—— 因为它 75ms 就走完，
  剩下的 165ms 是几乎不动的尾巴。所以：**要"更快"调曲线，要"更慢"先调时长**
  （`Motion.Slow` 240 → 280），把曲线再往缓推会变成"起步发木"。
- **别退回 `FastOutSlowInEasing`**（Material 内置那套偏软），也别用 `(0,0,0,1)`。

**时长**：

| 元素 | 时长 | 我们用的 token |
|---|---|---|
| 按压反馈 | 100–160ms | 弹簧 0.6/800 与 0.8/380（约 120ms 到位） |
| 提示条、小弹层 | 125–200ms | `Motion.Fast` 120 / `Motion.Base` 180 |
| 下拉、选择器 | 150–250ms | `Motion.Base` 180 |
| 弹层、抽屉、整页切换 | 200–500ms | `Motion.Slow` 240 |

**UI 动效一律 <300ms**，弹层/整页切换是唯一的例外档。

## 三、弹簧还是补间

- **手势驱动、可被打断、需要"活着"的感觉** → 弹簧（`spring(...)`）。
  弹簧被改目标时会带着当前速度继续走，这是它能被手指"抓住"的原因；
  `tween` 被重新触发会从零起跑，那一下顿挫就是"不丝滑"的来源。
- 其余（颜色、透明度、一次性的进入）→ `tween` + 上表的曲线。

**阻尼比口径**（苹果的说法，比 mass/stiffness/damping 三件套更好沟通）：

| 场景 | dampingRatio |
|---|---|
| 绝大多数 UI（菜单淡入、返回复位） | **1.0**（临界阻尼，不过冲） |
| 手势**自带惯性**时才允许一点点回弹（甩卡片、抽屉） | **0.8** |

我们的取值：按压 `PressDown 0.6/800`、`PressUp 0.8/380`（抄 M3 Expressive 的 spatial token）；
橡皮筋复位 `spring(1.0, 700)` —— 临界阻尼，**故意不弹**（欠阻尼会"复位后再抽一下"）。

## 四、手势：两段式

任何"跟着手指走"的东西都拆成两段，混了就一定手感不对：

```
手指还按着？──是──> 跟手段：位置 1:1 映射手指
                    不要缓动、不要时长、不要弹簧
             └─否──> 松手段：物理收尾
                    弹簧（带着松手速度）或补间；绝不用关键帧
```

- **边界用橡皮筋，不用硬墙**：`visual = raw·R·K/(R+K·raw)`（R=400dp、K=0.6），
  越拉越紧、导数为 0。[RubberOverscroll.kt](../app/src/main/kotlin/app/tavern/RubberOverscroll.kt)
  与苹果公开的 `o·D·K/(D+K·|o|)`（K=0.55）是同一个式子。
- **速度交接**：松手时把手指速度交给弹簧，衔接处才没有缝。
- **可打断**：新输入进来时从**当前值**接着算，从"目标值"重算会跳一下；
  光 `cancel()` 不够，还要代数守卫（见 [app/AGENTS.md](../app/AGENTS.md) 的橡皮筋一节）。
- **"怪异的弹簧"九成是阻尼太小**，先加阻尼再怀疑别的。

## 五、减动效（已接，2026-11-23）

系统开了「移除动画」（设置 → 无障碍 → 移除动画；或开发者选项里 Animator 时长缩放=关闭）时：

| 位置 | 正常 | 减动效 |
|---|---|---|
| 整页切换 / tab 切换 / 角色详情四标签 | 位移 + 淡淡入 | **纯交叉淡化** |
| 发送 ↔ 停止按钮 | 淡化 + 缩放 | **纯淡化** |
| 玻璃按压反馈 | 放大 1.25 | **不缩放**（描边与色仍在） |
| 列表两端的橡皮筋 | 跟手 + 弹簧回弹 | 跟手照旧，**松手直接归零** |

口径是"**更少更轻，不是全关**"：帮助理解的变化（淡化、手指直接拖出来的位移）保留，
位移与缩放这类"装饰性运动"去掉。

实现：`rememberReduceMotion()`（[ReducedMotion.kt](../app/src/main/kotlin/app/tavern/ReducedMotion.kt)），
取 `ValueAnimator.areAnimatorsEnabled()`，并在 `ON_RESUME` 重读（去设置里开关再回来即时生效）。
**渲染点统一用它，不要各自去读系统设置。**

验证方法：打开系统的「移除动画」→ 翻页应当只淡不滑，按压不再放大，
拉列表到头松手应当直接回位。

## 六、评审清单（动效版 Never Ship）

| 不要 | 换成 |
|---|---|
| `ease-in` 用在 UI 上 | 强 ease-out |
| 内置 / 极端的衰减曲线当"进入"曲线 | `Motion.Decelerate` |
| 100 次/天以上的操作加动效 | 不动 |
| `tween` 驱动可被打断的手势 | 弹簧（带速度） |
| 从"目标值"重算被打断的动画 | 从当前值接着算 |
| 阻尼 <1 的弹簧用在"归位"上 | 临界阻尼 1.0 |
| 关键帧式的动画（每帧重播） | 补间 + 重定向 |
| 全屏 `blur` 每帧重算还指望不掉帧 | 降采样 + 静态模糊；先量帧率 |
| 减动效只做在系统层面 | 自己手写的动效逐个降级 |
| `scale(0)` 当进入 | `0.9~0.97` + 透明度 |

## 七、我们有意的三处偏离

记下来，免得下一个人"按标准改回去"：

1. **按压是放大 1.25，不是缩小到 0.95~0.98**：用户明确要求"放大、不压暗"，且真机验收过。
2. **橡皮筋的参考尺寸固定 400dp**，不用容器高度：用户要求"每个页面能拉的距离一样"，
   用容器尺寸会让短内容页拉不动、长内容页拉过头。
3. **松手时丢掉"朝外"的速度**（只接受朝复位方向的速度）：标准做法是原样交接，
   但橡皮筋回 0 的场景下留着朝外速度会让内容在远端多停一截（"悬停"，2026-11-23 两轮才定位）。
