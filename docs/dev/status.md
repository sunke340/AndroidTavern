## 三级配置（这一夜的结构）

- 数据：`ConfigOverride`（每项 null = 跟随上级）+ 按作用域存 SharedPreferences
  （`session:<id>` / `card:<id>`），**不动 DB**。
- 解析：`UiState` 上只有 `effectiveProfileId / effectiveReasoningEffort / effectivePresetName /
  effectiveWorldBookNames / effectiveRegexIds / effectiveRegexScripts` 这几个 getter 回答"现在真正用什么"；
  发送、世界书扫描、正则（输入侧与显示侧）、连接参数全读它们。
- 切换会话时按覆盖重放连接参数与预设（`promptOrder` / 提示词 / 采样）；删会话顺手清覆盖。
- 卡级配置进 `openDetail`；卡级默认开场白也存这里（`greetingIndex`）。

## 消息操作（P0-6 现状）

| 动作 | 语义 | 证据 |
|---|---|---|
| 重新生成 | 不删行：新文本作为**新的 swipe 备选**追加，旧的可翻回 | `P0-6-swipes` 夹具（`swipes[] + swipe_id`） |
| 继续 | 请求末尾追加 system 提示 `[Continue your last message without repeating its original content.]`，结果**接在**最后一条后面 | `P0-6-continue` 夹具（11 条 messages + 落盘 `ok ok`） |
| swipe 翻页 | 只对最后一条助手消息（原版 `isMessageSwipeable`）；备选存 `message_swipes` 表（DB v3） | 同上 |
| 编辑 / 删除 | 编辑同步改当前 swipe 那一份；删除走玻璃确认框，备选级联删 | 手工 |

## 已知问题 / 风险

- **swipe 只对最后一条**：与原版一致，但长会话里想改中间那条只能编辑。
- **`continue` 的拼接是裸拼**（`旧文 + 新文`）：原版夹具里是 `ok ok`，模型一般会自带空格；
  若某些模型不给空格，读起来会粘在一起（未真机验证）。
- **消息没有稳定 key**：串流中往 transcript 加消息会插入一项（既有行为）。
- **卡级没有思考强度**：只有会话级（用户第 9 条只要会话级）。
- **编辑弹层不是玻璃**：它要浮起键盘、改长文本，玻璃面板在键盘上方既抢注意力又难量高度。
- 世界书开关会重解析；批量开启可能撑爆提示词（预算裁剪兜底）。outlet 位置只记录不注入。
- 玻璃帧率从未量过；未接预测式返回；日志只到事件级。
- **`apk-latest` 的 release body 在构建完成前就更新**（2026-11-25 实测：body 已有新 sha、资产还是上一次的）——
  `poll-ci.sh` 报 READY **不等于**新包已上传，**必须**下载后验 dex `BUILD_ID`。
- **本机编不了 `:app` / `:data`**：Android 侧编译错误只有 CI 会暴露（一轮约 4 分钟）。
