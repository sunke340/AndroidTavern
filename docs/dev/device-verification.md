## M0 · 2026-11-22 · 首次真机跑通

**APK**：`app-debug`（CI 出包，release `apk-latest`），约 11 MB，minSdk 26。
**链路**：PNG 卡（assets）→ `PngCard` → `CharacterCard` → `PromptBuilder` → `OpenAiCompatibleClient` → SSE 流式 → Compose 显示。
**provider**：OpenAI 兼容端点（用户填 baseUrl / key / model）。

### 结果：通过

| 检查项 | 证据 |
|---|---|
| 安装、启动 | 界面正常显示 |
| 卡片解析 | 状态行显示描述字数；「看请求」里出现完整描述 |
| 提示词组装 | 「看请求」显示 4 段：`main` → 描述（含 `[Seraphina's Personality= ...]`、`<START>`、示例对话）→ … |
| 请求发出 | 状态行 `完成（finish_reason=stop）` |
| 流式显示 | 回复逐字出现（用户确认） |
| 角色一致性 | 回复自称"塞拉菲娜，这片魔法森林——艾尔多利亚的守护者"，提到粉发、琥珀眼、治愈魔法、被野兽追赶——**全部来自卡里，不是模型自己编的** |

### 顺带确认的两个行为

1. 这张卡的 `description` **内含** `<START>` 与示例对话；原版把整个 description 当成一条 system 消息发出去，
   不做示例解析。我们照抄——「看请求」里能看到它原样在里面。
2. 用户用中文提问、卡是英文时，模型用中文回。这是模型行为（跟用户语言走），不是我们注入的语言指令。

### 这一轮暴露的问题

- CI 每次重新生成 debug keystore → 每次装新版都得先卸载（签名不一致）。待做：固定 debug 签名。
- `:core:ai` / `:core:card-format` 的公开 API 暴露了 `implementation` 依赖的类型
  （`OkHttpClient`、`JsonObject`），本机编不出来，只有 `:app` 会报 `Cannot access class X`。已修。

### 21 怎么测（`@@activate` / `@@dont_activate`）

1. 准备一份世界书 JSON，两条：
   - A 条：内容第一行写 `@@activate`，关键词随便填一个**不会出现**的词；
   - B 条：内容第一行写 `@@dont_activate`，关键词填你马上要说的词。
2. 设置 → 世界书 → 导入它并打开开关；用一张没有内嵌书的卡开新会话。
3. 发一句含 B 关键词的话 → 点聊天页 ⋮ →「查看本次请求」：
   - A 条**必须**出现（不用命中关键词）；
   - B 条**不能**出现（命中了也不行）。
4. 日志里也能对：`wi 开书 …` 后的扫描行会写命中条目数。

### 「撤回」怎么用（第 11 条的新按钮）

在任意一条**自己发的**气泡下面点「撤回」：这条和它后面的回复一起消失，正文回到输入框。
改完再发 = 新的时间线（和编程工具的 rewind 一样，不是"删一条"）。

### 已知限制（不用报）

- 卡级思考强度只影响**以后**发送的请求；已经在生成的那一轮不变。
- 开场白切换仍只允许"这条会话还没有用户消息"时用（B 策略）。
- 卡片写着「世界书 M 条」时 M 是内嵌条目总数，不是"参与提示词的条数"。

### 串卡 bug 的成因（第 8 条）

日志证据（`tavern-log-20261125-095554.txt`）：删掉 `synthetic.png` 之后，编辑并保存时写的是
`synthetic.bak.png`（备份文件被当成卡列出来了），而且保存后的卡"条目=4"。

根因两条：

1. **保存用的原始 JSON 是"会话那张卡"的**：`saveCardFields` 读的是 ViewModel 里的 `card` 字段，
   而它只在开会话/导入时更新，`loadDetail` 不更新。于是"先聊 Seraphina，再打开 Synthetic 编辑"
