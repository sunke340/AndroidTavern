## 三·六、不过的时候先看哪行日志（设置 → 关于 → 导出日志）

| 现象 | 先 grep | 看到什么说明什么 |
|---|---|---|
| 字还在抽搐 | `打印帧` | `供给足=是` 而 `实际` 明显低于 `目标速率` → 排版开销（按方案 §3.11 的阈值优化）；`供给足=否` → 是模型给得慢，不是我们的锅 |
| 打印中途突然补满 | `打印补齐` | `原因=` 会写明是哪条路（点气泡/停止/退页/换轮/swipe/无行/正文未变/切不限速/停滞） |
| 打印卡住不动 | `打印停滞` | 出现就是 bug，把这行发我（有剩余码点数和已等秒数） |
| 缕不上/多打一条 | `打印开始` / `打印续打` / `打印完成` | 一轮应该只有一条"开始"、至多一条"续打"、一条"完成（带用时）" |
| 分享进来的卡没导入 | `收到分享` | 有这行但没进详情 = 导入失败，看紧跟的 `导入失败`；没有这行 = 系统没把 SEND 给我们 |
| 朗读没声音 | `tts` | `TTS 初始化失败` / `speak 失败` 各自说明引擎问题 |
| 保存卡图失败 | `卡图已存相册` | 没有这行就看 Toast 的报错（权限/空间） |

## 四、已知的"看起来像 bug 但其实不是"

- 聊天页底部**输入区下面会露出正文**：设计如此（见 pitfalls「输入区盖住列表底部是设计」）。
- 打印期间**没有闪烁光标**：光标只在"生成中"那一行、`pendingKind == null` 时画；落库后进入"继续打印"就没有光标了。
- 慢档 2000 字要 133 秒：这是"慢"的字面含义（方案 §3.5 明确不设上限），逃生口是点一下气泡。
