## 症状

点发送之后，**整个列表先往下滑一点**，然后用户气泡才从输入胶囊后面升上来。

## 根因

不是"气泡入场慢了"，是**列表被推了一下**。每一轮开始时 `smoothHeight`（平滑高度基线）
还是 `0` —— 那是"**还没有**上一个高度"，但代码把它当成了"上一个高度 = 0"。占位气泡一量到
140px，`140 − 0` 就被算成"这一下长高了 140px"，同一帧里冒出两笔假位移：

1. `graphicsLayer` 的 `translationY` 把整列**往下推**（用户看到的就是这个）；
2. 「离开贴底」那条 `dispatchRawDelta` 会把同一个差量折成一笔**真滚动**。

原来靠 effect 里的一次 `snapTo` 事后对齐，可它要跨一次重组 + effect 派发才落地 ——
**至少一帧 140px 已经画出去了**。

日志指纹（用户提供的 19:58 那份日志里，每次发送都有，9 次一次不落）：

```
回底：新行/新一轮 near=true mine=true round=true
模式=A idx=0 off=0 气泡高=140 平滑差=140px
```

140px = 占位气泡高度，`平滑差=140px` = 首次测量减掉 0 基线。

## 改法

差量只在**基线建立之后**才算，而且是**同步判断**（不指望 effect 的时序）：

- 新增 `bridgePendingPx()`：`smoothHeight <= 0` 时恒为 `0`；四处（`translationY`、
  「离开贴底」折算、「回到贴底」诊断、模式日志）统一走它。
- 返回 **Float**：`translationY` 要亚像素差（取整会让串流跟随一格一格跳）；折滚动那边沿用
  原来的 `.toInt()`。
- 首测对齐补一条事件日志：`scroll 首测：对齐 140px（基线未建立，不按增长处理）`。
