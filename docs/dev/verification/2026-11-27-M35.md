## 一、导入后详情页要立刻是对的

**根因**：`importCard` 只写了 `detailCardId`，没走"打开详情"（日志里那次 push 没有 `读详情`），
页面拿到的是上一次的 `detail` → 开场白/内嵌书全空；重进才有。

| # | 怎么造 | 过 = 看到什么 |
|---|---|---|
| 1 | 分享测试卡 → 确认导入 | 进详情页后**立刻**有：开场白（含多条时的 `‹ N/M ›`）、「会话」tab 的会话数、「世界书」tab 的内嵌条目数 |
| 2 | 看日志 | 导入成功之后应当紧跟一行 `读详情 <id> Nms 条目=…` |
| 3 | 连续导入两张不同的卡 | 第二张的详情**不是**第一张的内容（开场白、条目数都跟着换） |

**11 = `SpeechRecognizer.ERROR_SERVER_DISCONNECTED`**（识别服务与服务端断开）。时间线：
`16:31:05.946 麦克风权限：已允许` → `16:31:21.653 语音识别出错：未知错误 11`，
中间 15.7 秒 —— 引擎是在听的，最后服务端那一步掉了。

`apk-m228` 针对这条改了四处：

1. **机内识别优先**：API 31+ 且 `isOnDeviceRecognitionAvailable` 为真时用
   `createOnDeviceSpeechRecognizer` + `EXTRA_PREFER_OFFLINE` —— 不连服务端就不可能服断；
2. 错误码 11–14 补了名字（服断 / 语言不支持 / 语言包没装 / 无法检查语言支持）；
3. **服断/网络类错误自动重试一次**（只一次，别让人等两回十几秒）；
4. 日志补 `机内=… 引擎=<包名>` 与 `语音识别：开始听（机内/服务端）`、`首个中间结果 N 字` ——
   下一轮就能判断是"引擎要求联网"还是"我们用法不对"。

**请在 `apk-m228` 上复验 §三 的 #7–12。** 若仍是 11，把这行发我：
`ui 语音识别 可用=… 服务=… 意图=… 机内=… 引擎=…`。

## 回执（v188，装 `apk-m228`）

两次尝试，形态都是「点了、一个字都不出来」：

| 时刻 | 事件 |
|---|---|
| 12:07:14.963 | `开始听（服务端）` → 12:07:20.928 离开页面（5.9s） |
| 12:18:38.373 | `开始听（服务端）` → 12:18:49.880 离开页面（11.5s） |

十一秒内**零回调**：没有 `首个中间结果`、没有 `语音识别出错：…`、也没有 `语音输入 N 字`。
引擎是 `com.vivo.ai.copilot`，`机内=false 意图=0`。对照 v187：那个 11 是**开始听 15.7 秒后**才报的，
这两次都在 15.7 秒之前就离场了（所以不是前后矛盾，是没等到它开口）。

两个候选，`apk-m229` 一次打两处：

1. **绑定竞态（主候选）**：`createSpeechRecognizer` 之后同一帧就 `startListening`，
   而 AOSP 在服务还没连上时走 `checkOpenConnection()` 失败 —— **只写 logcat，不抛异常、不回调**；
2. vivo 的云端引擎本身对第三方不可用（11 是它的常态）。

`apk-m229` 的改动：

- 建完识别器**延后 150ms** 再 `startListening`（用户感觉不到，足够服务绑上）；
- **4 秒一个回调都没有就放弃**并自动重试一次，不再对着空气等 15 秒；
- 每个回调都记：`首个回调 服务就绪 / 听到声音 / 音量 / 说完了（Nms）`、
  `结果 N 字（Nms，备选 N 条，音量峰值 X）`、`错误 X（Nms，回调见过=真/假，音量峰值 X）`；
  「听到声音」和「服务就绪」分开记 —— 这两句能把"麦克风没开"和"引擎不应答"分开；
- `EXTRA_PREFER_OFFLINE` 只在真走机内识别时才加（键存在本身就等于提要求）。

复验（装 `apk-m229`）：

| # | 怎么造 | 过 = 看到什么 |

| 12a | 聊天页 ⋮ →「语音输入」，说一句话 | 边听边出字；日志有 `首个回调 听到声音（…ms）` 与 `首个中间结果 N 字` |
| 12b | 不说话，等 5 秒 | 先提示"语音服务没响应，再试一次…"，第二次仍无回调则提示"语音服务没响应，这台机器的识别引擎用不了" |
| 12c | 把这四行发我 | `开始听（…）`、`首个回调 …（Nms）`、`错误 …（Nms，回调见过=…）`、`结果 …` |

## apk-m230：把窗口放到引擎自己的失败点之后（25 秒）

这一轮只做**判定**，不做修复：

- 静默窗口 `4s → 25s`（比 15.7s 的失败点长），期间**每个回调都记**（已在 `apk-m229` 埋好）；
- **关掉自动重试**（上一版两个 4 秒窗口叠在一起，反而干扰判读）；`voiceRetried` 一并删掉；
- 起飞前多记一格：`语音识别 … 默认=<系统配置的默认识别组件>`（读 `Settings.Secure`
  的 `voice_recognition_service`）—— `引擎=` 只说明"这个包里有服务"，不一定就是框架找的那个。

四种结局各自指向一个结论（这一轮就是要把它们分开）：

| 25 秒里看到 | 结论 |
|---|---|
| `首个中间结果` / `结果 N 字` | 能用，只是握手慢（≥4s）；调窗口与提示即可，不用换方案 |
| `错误 没听到声音`（`ERROR_SPEECH_TIMEOUT`） | 引擎活着、麦克风也开着，只是没听到 —— 说响一点再试 |
| `错误 识别服务断开`（11） | 它真到不了自己的服务端 → 第三方用不了，只能换方案 |
| 25 秒仍零回调 | `startListening` 或绑定确实没生效，往那条线查（`默认=` 这一格就是为它准备的） |

| # | 怎么造 | 过 = 看到什么 |
|---|---|---|
| 12d | 装 `apk-m230`，进聊天页看一行 | `语音识别 可用=true 服务=1 意图=0 机内=false 引擎=… 默认=…` |
| 12e | ⋮ →「语音输入」，**说一句话并等满 25 秒**（别中途退出，这次就是要看它怎么收场） | 日志里按上表出现其中一种结局 |

## 回执（v190，装 `apk-m230`）—— 25 秒里全程没说话，仍然零回调

进聊天页那行把**框架实际会去找谁**钉死了：

```
语音识别 可用=true 服务=1 意图=0 机内=false
  引擎=com.vivo.ai.copilot 默认=com.vivo.ai.copilot/.framework.wakeup.CopilotRecognitionService
```

两次尝试（用户**全程没说话**）：

| 时刻 | 事件 |
|---|---|
| 15:45:42.033 | `开始听（服务端；…）` |
| 15:46:07.206 | `25 秒没有任何回调（连 onReadyForSpeech 都没来），放弃` |
| 15:46:33.217 | 再听一次 |
| 15:46:58.391 | 又是 25 秒零回调 |

能确定的三条：

1. **不是"找错了服务"**：默认组件就是 vivo 那个具体实现，`isRecognitionAvailable` 也为真；
2. **不是"在听但没听到声音"**：那种形态会先来 `onReadyForSpeech`、再来 `错误 没听到声音`
   （`ERROR_SPEECH_TIMEOUT`）。这里连 `onReadyForSpeech`、`onRmsChanged`、`onError` **一个都没有**
   —— 25 秒里一句都没有；
3. 用户没说话，所以"没出字"是预期的；**"连 ready 都没有"才是异常**。

于是不必再猜"是不是窗口切早了"：现在要分的是 **`startListening` 到底发出去没有**。
AOSP 在服务未连上时 `startListening` 只写 logcat —— 不抛异常、不回调，和"发出去但引擎不出声"
在界面上完全同形。

## apk-m231：补发 startListening + 麦克风自检

- **补发**：`startListening` 最多发 3 次、间隔 1.2 秒，**拿到任何回调就停**，每次都记
  `语音识别：第 N/3 次 startListening（Nms）`。若引擎其实已受理，补发通常会回 `识别器忙` ——
  那本身就是"第一发到了"的铁证（对应的提示改成"引擎收下了请求但一直没出声"）。
- **麦克风自检**：开听前在工作线程用 `AudioRecord` 录 1.2 秒，记
  `麦克风自检 可以录：N 采样/Nms 峰值=N 均方根=N`（或 `不可用（…）`）。
  它把"我们这条线录不到"与"引擎不说话"分开 —— 后面若选内置离线引擎，就押在这一格上。
  自检读完即释放，不与识别器抢麦克风。
- 25 秒窗口保持不变（这一次它是量"补发 3 次之后还沉默多久"，不是量"第一发之后"）。
